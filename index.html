Experiment 1: Application Penetration Testing for Network Footprinting (Reconnaissance) and Vulnerability Assessment

Step 1: Start the terminal.
Step 2: Check the host information.
host google.com
Step 3: Trace the network path.
traceroute google.com
Step 4: Display network interface information.
ifconfig
Step 5: Find domain registration information.
whois google.com
Step 6: Collect information about the target domain.
theHarvester -d google.com -b google
Step 7: Scan the target for services and vulnerabilities.
nmap -A -T4 142.251.220.110
Or use:
nmap -F 142.251.110.220
Step 8: Check the web server for known vulnerabilities.
nikto -h https://www.google.com
Step 9: Observe and analyse the results.
Step 10: Stop.
Result: Network information and possible vulnerabilities are identified.
Note: Perform scans only on systems and domains for which you have permission. The commands are reproduced from the supplied lab document.

Step 1: Start the terminal.
Step 2: Check the website response.
curl -s http://www.google.com

curl -I http://www.google.com
Step 4: Update the package list and install OWASP ZAP.
sudo apt update && sudo apt install zaproxy

OWASP ZAP -h
Step 6: Check the ZAP command-line help.
zaproxy -h
Step 7: Check the WPScan version.
wpscan --version
Step 8: Use the scanning tools to check the configuration and deployment of an authorised test website.
Step 9: Observe and analyse the results.
Step 10: Stop.
Result: Configuration and deployment weaknesses are checked using security scanning tools.
Note: The OWASP ZAP help command is shown as written in the previous algorithm; the supplied document also lists zaproxy -h.

Experiment 3: Enumerate Infrastructure and Application Admin Interface

Step 1: Start the terminal.
Step 2: Download the Recon-ng tool from GitHub.
git clone https://github.com/lanmaster53/recon-ng
Step 3: Open Recon-ng.
recon-ng
Step 4: Check the available workspaces.
workspaces
Step 5: Search for available modules.
marketplace search
Step 6: Install the required module.
marketplace install recon/companies-domains/viewdns_reverse_whois
Step 7: Load the module.
modules load recon/companies-domains/viewdns_reverse_whois
Step 8: Set the target domain.
options set SOURCE google.com
Step 9: Run the module.
run
Step 10: Display the discovered host information.
show hosts
Step 11: Open the OWASP Juice Shop website.
https://demo.owasp-juice.shop
Step 12: Check the application users endpoint.
curl -i -X POST http://demo.owasp-juice.shop/api/Users/
Step 13: Check the current user information.
curl -i http://demo.owasp-juice.shop/rest/user/whoami
Step 14: Check the login endpoint.
curl -i -X POST http://demo.owasp-juice.shop/rest/user/login
Step 15: Check the registration page.
curl -i demo.owasp-juice.shop/#/register
Step 16: Exit the terminal process.
exit
Result: Infrastructure and application information is collected and analysed.
Note: Use authorised test environments. The OWASP Juice Shop demo is intended for security practice.

Experiment 4: Authentication and Authorization Testing

Step 1: Start the terminal.
Step 2: Open the John the Ripper tool.
john
Step 3: Generate an MD5 password hash.
openssl passwd -1 password123
Step 4: Create a file to store the hash.
nano hash.txt
Step 5: Save the generated hash inside the file and close it.
Step 6: Crack the hash using John the Ripper.
john --format=md5crypt hash.txt
Step 7: Display the cracked password.
john --show hash.txt
Step 8: Check the available wordlists.
ls /usr/share/wordlists/
Step 9: Extract the RockYou wordlist.
sudo gzip -dk /usr/share/wordlists/rockyou.txt.gz
Step 10: Crack the hash using the RockYou wordlist.
john --format=md5crypt --wordlist=/usr/share/wordlists/rockyou.txt hash.txt
Step 11: Display the password result.
john --show hash.txt
Step 12: Enable and start the SSH service on the authorised lab machine.
sudo systemctl enable --now ssh
Step 13: Check the SSH service status.
sudo systemctl status ssh
Step 14: Display the IP address.
ip addr
Step 15: Create a password list.
nano passwords.txt
Step 16: Enter the following passwords into the file.
password
studentpassword123
letmein
123456
Step 17: Check the SSH service version on the lab machine.
nmap -sV -p 22 172.20.11.33
Step 18: Test the lab SSH account against the password list. Use only an account and machine you are authorised to test.
hydra -l student -P passwords.txt ssh://172.20.11.33 -t 4
Step 19: Connect to the SSH machine.
ssh student@172.20.11.33
Step 20: Exit the SSH connection.
exit
Result: Authentication and authorization weaknesses are tested, and password security is analysed.
Safety note: Password auditing and SSH login testing must be limited to your own lab accounts or systems for which you have explicit permission.
